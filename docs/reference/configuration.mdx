---
title: "Configuration"
description: "Reference for the small BachsProof v2 configuration object."
---

| Property | Required | Meaning |
| --- | --- | --- |
| `webhookUrl` | yes | Complete HTTP(S) URL of the isolated webhook route |
| `secret` | yes | Test-only webhook signing secret |
| `amountMinor` | yes | Non-negative safe integer amount in minor units |
| `currency` | yes | Three-letter ISO currency code |
| `createPayment` | yes | Creates a fresh application payment and returns its reference |
| `verify` | yes | Reads committed financial state |
| `scenarios` | no | Scenario identifiers to run; omitted means the five default scenarios |
| `verificationTimeoutMs` | no | Extra time for asynchronous financial processing |

Provider adapters, signing objects, scenario definitions, replay settings,
checkpoints, race controllers, and synthetic-reference switches are not part of
the v2 configuration. BachsProof signs generated test events automatically.

The `secret` is for the test endpoint only. Your application should continue to
verify Bachs webhook signatures as described in the official
[webhook guide](https://docs.bachs.io/guides/webhooks/overview). The Bachs API
key and the API's [Idempotency-Key](https://docs.bachs.io/guides/idempotency)
are separate provider-side concerns.

The default suite is sequential duplicate webhook, concurrent duplicate credit,
concurrent unique payments, incorrect payment amount, and incorrect payment
currency. Add optional scenarios such as `underpaid-payment` or
`failed-payment` when your integration supports those provider states. The
`--name` CLI option can run any supported scenario, even when it is not in the
configured subset.
