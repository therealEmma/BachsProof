---
title: "Programmatic testing API"
description: "Run BachsProof from Vitest, Jest, or another TypeScript test runner."
---

In simple English, the programmatic API lets Vitest, Jest, or another test
runner call BachsProof directly instead of starting the CLI. Import
`BachsProof`, configure an adapter and target, then call `run`:

```ts
import { BachsProof } from "@bachsproof/core";
import { bachsAdapter } from "@bachsproof/bachs";

const runner = new BachsProof({
  provider: bachsAdapter({ mode: "mock" }),
  target: {
    baseUrl: "http://127.0.0.1:3000",
    webhookPath: "/webhooks/bachs"
  },
  createPayment: async ({ amountMinor, currency }) =>
    (await createIsolatedPayment({ amountMinor, currency })).reference,
  verify: async (reference) => inspectCommittedState(reference),
  financialVerification: {
    completionDeadlineMs: 10_000,
    pollIntervalMs: 25,
    negativeObservationWindowMs: 250
  }
});

const result = await runner.run({
  scenario: "concurrent-duplicate-credit",
  amountMinor: 500_000,
  currency: "NGN",
  concurrency: 2
});

if (!result.passed) {
  console.error(result.report.errors, result.report.verification?.violations);
}
```

`createIsolatedPayment` and `inspectCommittedState` in this example are
application test helpers, not BachsProof exports. A real reference can also be
passed directly. Use `syntheticReferences: true` only for fixture-only runs.

## Important methods and results

| Surface | Meaning |
| --- | --- |
| `new BachsProof(options)` | Stores the adapter, target, callbacks, polling, and optional checkpoint configuration |
| `runner.run(input)` | Prepares references, delivers the scenario, verifies state, and returns `BachsProofResult` |
| `result.passed` | False for configuration/preparation/delivery errors or failed financial verification; may be true without financial proof if no verifier exists |
| `result.report` | Structured deliveries, observations, violations, checkpoint trace, and replay metadata |
| `runner.replay(report)` | Reuses the structured event and schedule metadata; it does not reset application state |

`RaceController`, `verifyPaymentState`, `verifyWithCallback`, `writeReport`,
and `redactSecrets` are lower-level exports for advanced integrations. The
optional checkpoint SDK is separate: core controls the barrier, while the SDK
lets the application announce an instrumented arrival.
