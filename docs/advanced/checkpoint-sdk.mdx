---
title: "Checkpoint SDK"
description: "Add optional request-scoped checkpoint instrumentation for a test-only race schedule."
---

`@bachsproof/sdk@1.1.0` is a small optional package. It has no Express
dependency. Its middleware accepts a generic request shape, so it can be
adapted to Fastify, NestJS, or another HTTP framework.

You need it only when ordinary concurrent HTTP delivery does not reliably reach
the application point you want to test. It must never be enabled in production.

## Two opt-in switches

```ts
import {
  checkpoint,
  checkpointMiddleware,
  configureCheckpoint
} from "@bachsproof/sdk";

const testMode = process.env.BACHSPROOF_TEST_MODE === "true";

configureCheckpoint({
  enabled: false,
  allowRequestHeaders: testMode
});

app.use(checkpointMiddleware({
  enabled: testMode,
  timeoutMs: 10_000
}));

app.post("/webhooks/bachs", async (req, res) => {
  const payment = await readPayment(req.body.data.reference);
  await checkpoint("after-idempotency-check", {
    key: payment.reference,
    metadata: { route: "/webhooks/bachs" }
  });
  await processPayment(payment);
  res.sendStatus(200);
});
```

The application must enable the middleware and explicitly allow request
headers. BachsProof's runner supplies the headers only for controlled runs:

```text
x-bachsproof-enabled
x-bachsproof-controller
x-bachsproof-session
x-bachsproof-participant
x-bachsproof-token
```

The token is scoped to the registered session and the participant ID must be on
that session's allow-list. These headers are test protocol details, not public
application API fields.

## What each SDK concept does

| Concept | Meaning |
| --- | --- |
| Checkpoint | A named application line where a request announces arrival and waits |
| Participant | One delivery in the controlled run |
| Barrier | The “wait until N participants arrive” rule |
| Race controller | Core's local HTTP service that authenticates arrivals and releases them |
| Request-scoped context | Controller URL, session, participant, token, and timeout stored for one request |
| Middleware | Reads opt-in headers and creates the request context |
| `checkpoint` | Posts arrival and waits for the controller response |
| `configureCheckpoint` | Sets process-wide configuration or allows request headers |

`AsyncLocalStorage` keeps two concurrent requests in the same Node process from
sharing participant credentials. Disabled calls return before any network
request.

## The actual communication

1. `BachsProof.run` creates a `RaceController` and calls `registerSession`.
2. The controller returns a local URL, session ID, token, and participant list.
3. Core `deliver` adds the `x-bachsproof-*` headers to each webhook.
4. `checkpointMiddleware` creates a context for each request.
5. `checkpoint` posts `{ participantId, key, metadata }` to the controller.
6. `RaceController.handle` authenticates the bearer token, records the arrival,
   and holds the HTTP response.
7. `waitForArrivals` resolves when the required count is present.
8. Core calls `release`; the controller finishes the held responses.
9. `checkpoint` returns and the application continues to its database write.
10. Core stores the arrival/release/abort trace and cleans up the session.

The implementation is `packages/sdk/src/checkpoint.ts`; the HTTP barrier is
`packages/core/src/race-controller.ts`.

## Exported helpers

- `configureCheckpoint(config)`: set explicit process configuration.
- `disableCheckpoints()`: clear process-wide context and header permission.
- `isCheckpointEnabled()`: inspect whether a context is active.
- `runWithCheckpointContext(context, callback)`: run code under a supplied
  context, useful for framework adapters and tests.
- `checkpoint(name, options)`: announce and await a named barrier.
- `checkpointMiddleware(options)`: install request-header context handling.
- `getCheckpointContext()`: inspect the current read-only context.

<Warning>
This SDK is a synchronization aid for isolated tests. It is not a production
lock, authorization mechanism, queue, or payment guarantee. Keep the test mode
switch, controller credentials, and header trust inside an authorized test
process.
</Warning>
