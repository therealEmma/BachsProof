---
title: "Custom provider adapters"
description: "Extend BachsProof with another documented provider contract."
---

The core is provider-neutral. A custom adapter must define the event shape and
wire behavior; BachsProof will not invent a provider contract or guess event
eligibility.

```ts
import type { ProviderAdapter } from "@bachsproof/core";

export const myAdapter: ProviderAdapter<MyEvent> = {
  name: "MyProvider",
  mode: "test",
  createPayment(input) {
    return createDocumentedTestEvent(input);
  },
  serialize(event) {
    return JSON.stringify(toProviderEnvelope(event));
  },
  expectedState(event) {
    return {
      reference: event.reference,
      eligible: event.status === "paid",
      amountMinor: event.amountMinor,
      currency: event.currency,
      expectedCreditCount: event.status === "paid" ? 1 : 0
    };
  },
  headersForBody(_event, body) {
    return signDocumentedBody(body);
  },
  createScenario(scenario, input) {
    return documentedScenarioPlan(scenario, input);
  }
};
```

The helper names in this example are application/provider code. The required
adapter methods are the BachsProof contract. `createPayment` must return the
provider event object; `serialize` must produce the exact body your application
expects; `expectedState` describes the financial outcome; `headersForBody` is
the safe place to sign the exact body; and `createScenario` may define ordered
or concurrent deliveries, body overrides, delays, expected statuses, and
verification events.

Start with one scenario and tests for passing, failing, malformed, and
signature cases. Only describe a provider as supported after checking its
authoritative event contract and the adapter's real serialized output.
