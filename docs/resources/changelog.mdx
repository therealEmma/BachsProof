## v2.1.0

The v2.1 release keeps the v2 architecture and makes the default test run more
focused and the Bachs-shaped fixtures more accurate.

### Scenario changes

- Five scenarios now run by default: sequential duplicate webhook, concurrent
  duplicate credit, concurrent unique payments, incorrect payment amount, and
  incorrect payment currency.
- Cross-event duplicate payment, out-of-order events, checkout completed
  without payment, expired checkout, underpaid payment, and failed payment are
  optional. Use `scenarios` or run any supported identifier with `--name`.
- The checkout-without-payment fixture now models a free completed checkout:
  amount `0`, `no_payment_required`, no charge, and a completion timestamp.
- The underpaid fixture remains limited to the documented crypto partial-payment
  event. Amount and currency scenarios are deliberately modified, valid-shaped
  events for application-side validation.

### Reporting and compatibility

- Human-readable reports now show delivery results, financial verification,
  exact expected and observed counts and amounts, discrepancies, invariant
  identifiers, explanations, and duration.
- Ineligible outcomes are reported as zero expected credits totaling zero in the
  configured currency. Missing evidence is never displayed as zero.
- JSON result objects, secret redaction, exit codes, callbacks, signing, and the
  five invariant identifiers remain compatible with v2.0.0.
- The publishable packages affected by this release are `@bachsproof/core`,
  `@bachsproof/bachs`, and `@bachsproof/cli`; they are marked `2.1.0` locally
  but have not been published.

## v2.0.0

BachsProof became a focused application-side financial correctness tool.

### Simplified integration

- Install `@bachsproof/cli` as the normal entry point.
- Run `bachsproof init` to create one `bachsproof.config.mjs` file.
- Configure a complete `webhookUrl`, test `secret`, amount, and currency.
- Implement only `createPayment()` and `verify()`.
- Signing, the Bachs adapter, the default scenario suite, polling, and reports
  are handled by the CLI.
- At the v2.0 release, all eleven scenarios ran by default; v2.1 narrows the
  default suite to five and keeps the other six selectable.

### Removed functionality

The active v2 workspace no longer includes the BachsProof SDK, checkpoints,
controlled race release, replay configuration, synthetic references,
delivery-only mode, or the four removed security/delayed-payment scenarios.
Ordinary concurrent delivery, webhook signing utilities, asynchronous
verification, and structured reports remain.

### Breaking migration steps

1. Replace the old generated files with one `bachsproof.config.mjs`.
2. Replace separate target URL/path settings with `webhookUrl`.
3. Remove provider, signing-object, replay, checkpoint, race-controller,
   synthetic-reference, and custom-test configuration.
4. Add `createPayment()` to create a fresh application payment reference.
5. Add `verify(reference)` to read committed payment and ledger state.
6. Remove `requireFinancialVerification`; financial verification is mandatory.
7. Update report consumers from version 1.1 to 2.0 and remove fields that only
   described checkpoints, replay, delivery-only runs, or synthetic references.
8. Replace references to the four removed standalone scenarios with the eleven
   current scenarios.

The five financial invariants keep their existing identifiers and meanings.
The v1.1.0 release history remains available; v2 is a breaking release and is
not published by this repository automatically.
