---
title: "Frequently asked questions"
description: "Common questions about BachsProof and payment testing."
---

<AccordionGroup>
  <Accordion title="Does BachsProof move real money?">
    No. The Bachs adapter uses local synthetic fixtures in `mock` mode. Your
    `createPayment` callback must also use an isolated test API or database and
    must not start a real financial transaction.
  </Accordion>
  <Accordion title="Do I need a Bachs account?">
    No for the local adapter. Use a Bachs sandbox separately when you need to
    test provider-side checkout creation, settlement, or genuine sandbox
    delivery behavior.
  </Accordion>
  <Accordion title="What does ₦5,000 look like in a test?">
    `500_000` NGN minor units when the currency uses two decimal places. Set the
    amount explicitly; the current Bachs fixture default is `5_000_000`.
  </Accordion>
  <Accordion title="Does BachsProof replace Vitest or Jest?">
    No. The CLI is standalone and the core can be called from an existing test
    framework. Let Vitest or Jest manage application setup and teardown.
  </Accordion>
  <Accordion title="Do I need to modify my application?">
    No for black-box testing. Checkpoint testing is optional and requires
    explicit test-only SDK instrumentation.
  </Accordion>
  <Accordion title="Why do I need a verification callback?">
    HTTP success only proves that a route acknowledged a request. The callback
    independently reads committed payment or ledger state.
  </Accordion>
  <Accordion title="Can BachsProof test Go or Python?">
    Yes. The target is an HTTP endpoint. The callback can run in the Node-based
    test project and read a shared test database or authorized test service.
  </Accordion>
  <Accordion title="What if processing is asynchronous?">
    Return `pending: true` while the worker is still processing and
    configure a bounded completion deadline. Negative scenarios also use a
    bounded no-credit observation window.
  </Accordion>
  <Accordion title="Why did HTTP 200 still produce a failure?">
    The application acknowledged the request but the verifier observed missing,
    duplicate, or incorrect financial state.
  </Accordion>
  <Accordion title="Do I need the checkpoint SDK?">
    No. Use it only when you want to coordinate a named application execution
    point. Ordinary black-box concurrency remains the default.
  </Accordion>
</AccordionGroup>
