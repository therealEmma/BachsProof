# Beyond webhook delivery. Verify financial correctness.

BachsProof sends simulated payment webhooks to an isolated application and
checks the financial records the application actually committed. If a customer
pays NGN 5,000 and the same webhook arrives twice, the customer should still
receive one NGN 5,000 credit. BachsProof checks that result in your records.

The official [Bachs documentation](https://docs.bachs.io/) explains how to
create checkout sessions, authenticate API requests, receive signed webhooks,
and understand Bachs event types. BachsProof focuses on what happens after
your application receives an event: whether your own payment records and
ledger stay correct.

It is an independent, unofficial test tool. It does not call Bachs, move
money, delete data, or certify production readiness.

## The v2 workflow

1. Install `@bachsproof/cli`.
2. Run `bachsproof init` to create one config file.
3. Implement `createPayment()` and `verify()`.
4. Run one scenario or the five-scenario default suite.

The CLI configures Bachs event generation and signing automatically. Every
passing test includes completed financial verification.
