# Payment correctness beyond HTTP responses

BachsProof is an independent, unofficial testing framework for Bachs integrations. It sends payment-shaped
requests to an isolated copy of your application and, when you configure a
verifier, reads the financial records your application actually saved.

It is not affiliated with or endorsed by Bachs.

That second part matters. A webhook returning `200 OK` only says that an HTTP
request was acknowledged. It does not tell you whether a wallet was credited,
whether the amount was correct, or whether a retry created a second credit.

For example, if a customer deposits **₦5,000** into a wallet, the application
should normally create one ₦5,000 credit. BachsProof can send the same payment
notification twice, send two notifications at once, and then check the saved
credits instead of trusting the two HTTP responses.

<Note>
BachsProof is a testing tool. It does not move real money, create live Bachs
payments, or certify that an application is production-ready.
</Note>

## What BachsProof does

- Sends synthetic, documented-shaped webhook requests over HTTP.
- Tests the Bachs-shaped events supported by `@bachsproof/bachs`.
- Runs duplicate, concurrent, ordering, amount, currency, signature, and
  payment-state scenarios.
- Lets your test code create fresh application payments through `createPayment`.
- Lets your test code read committed credits or ledger entries through `verify`.
- Compares that observed state with five financial rules, called invariants.
- Offers an optional test-only checkpoint for coordinating a particular race.

## What BachsProof does not do

- It does not move real money or charge a card.
- Its Bachs adapter does not call Bachs, create a checkout, or settle a payment.
- It does not add routes, change your production code, manage your database, or
  reset test data.
- It cannot understand an application's database automatically. You provide the
  small `verify` callback that knows your schema.
- It cannot prove behavior that the selected scenario and observation window did
  not test.

The word **synthetic** means “made for the test.” A synthetic webhook can be
useful for checking your handler, authentication, and database logic, but it is
not evidence that Bachs collected money. Use a Bachs sandbox separately when
you need provider-side checkout or settlement evidence.
