## 1. Prepare an isolated application

Use a test server, test database, test queue, and test-only webhook secret.
BachsProof never creates a payment in your application. Your callback creates
the record first.

## 2. Create the config file

```bash
pnpm add -D @bachsproof/cli
pnpm exec bachsproof init
```

Open `bachsproof.config.mjs`. Set the four values and replace the two generated
errors with your application code. `createPayment()` must insert a fresh test
payment and return its reference. `verify()` must read the saved payment and
ledger state. See [Preparing payments](/testing/preparing-payments) and
[Verifying financial records](/testing/verifying-financial-records) for the
complete examples.

## Integrate with an AI coding agent

This step is optional. You can ask Codex, Claude Code, Cursor, or another AI
coding agent to implement the two callbacks using your application's existing
database, payment, webhook, and ledger architecture.

Copy this prompt into your preferred agent:

```text
Help me integrate BachsProof into my application using the project documentation:

https://bachs-proof.mintlify.site/

Read the documentation before implementing the `createPayment()` and `verify()` functions in `bachsproof.config.mjs`.

Review my database schema, payment logic, webhook handler and ledger implementation.

The `createPayment()` function should prepare a fresh pending test payment and return its unique reference.

The `verify()` function should retrieve actual financial records from the database, including all credits associated with the payment, even duplicate or unexpected credits.

Do not rely solely on payment status, a single transaction reference or hardcoded expected results.

Follow the documentation, use an isolated test database and keep the implementation simple.
```

Review the generated implementation yourself. Make sure the isolated
application is running, then run:

```bash
npx bachsproof test
```

## 3. Run one scenario

```bash
pnpm exec bachsproof test --name "sequential duplicate webhook"
```

This creates one payment, sends the same signed webhook twice, reads the saved
records, and checks that one credit exists.

## 4. Run all eleven scenarios

```bash
pnpm exec bachsproof test
```

Use `--json` in CI or when saving a report for debugging.
