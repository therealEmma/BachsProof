---
title: "Quickstart"
description: "Configure two callbacks and run a real financial correctness test."
---

## 1. Prepare an isolated application

Use a test server, test database, test queue, and test-only webhook secret.
BachsProof never creates a payment in your application. Your callback creates
the record first.

## 2. Create the config file

```bash
pnpm add -D @bachsproof/cli
pnpm exec bachsproof init
```

Open `bachsproof.config.mjs`. Set the four values and replace the two generated
errors with your application code. `createPayment()` must insert a fresh test
payment and return its reference. `verify()` must read the saved payment and
ledger state. See [Preparing payments](/testing/preparing-payments) and
[Verifying financial records](/testing/verifying-financial-records) for the
complete examples.

## 3. Run one scenario

```bash
pnpm exec bachsproof test --name "sequential duplicate webhook"
```

This creates one payment, sends the same signed webhook twice, reads the saved
records, and checks that one credit exists.

## 4. Run all eleven scenarios

```bash
pnpm exec bachsproof test
```

Use `--json` in CI or when saving a report for debugging.
