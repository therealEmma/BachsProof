---
title: "Running PayProof in CI/CD"
description: "Build a safe, repeatable payment correctness job."
---

Run PayProof against a dedicated test application and database. The application
may be started as a CI service, a preview deployment, or a local process in
the job.

```yaml
# Illustrative CI steps
- run: pnpm install --frozen-lockfile
- run: pnpm exec payproof test --json > payproof-results.json
  env:
    PAYPROOF_TARGET_URL: http://127.0.0.1:3000
    BACHS_WEBHOOK_SECRET: ${{ secrets.PAYPROOF_WEBHOOK_SECRET }}
```

Recommended controls:

- create fresh payment records through `createPayment`;
- use an isolated database or a scoped cleanup strategy;
- use test-only secrets and synthetic events;
- set `requireFinancialVerification: true`;
- retain the JSON output as a CI artifact;
- fail the job when the CLI exits non-zero;
- never expose database URLs or webhook secrets in logs.

The suite runs configured scenarios sequentially by default, which reduces
cross-scenario contamination. Concurrency still occurs inside scenarios that
require it.
