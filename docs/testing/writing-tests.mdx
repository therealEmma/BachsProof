---
title: "Writing payment tests"
description: "Configure one scenario or a complete suite."
---

The CLI test file exports an array of named `BachsProofCliTest` objects. The
`name` is used by `--name`; the remaining fields are `RunOptions`.

Start with one delivery-only test if you are learning the setup. Add a real
reference and `verify` when you want a financial result. Add `checkpoint` only
after ordinary concurrent delivery is working and you need one repeatable
application schedule.

```js
export const tests = [
  {
    name: "one ₦5,000 payment is credited once",
    scenario: "sequential-duplicate-webhook",
    amountMinor: 500_000,
    currency: "NGN"
  },
  {
    name: "concurrent duplicates stay idempotent",
    scenario: "concurrent-duplicate-credit",
    concurrency: 3,
    amountMinor: 500_000,
    currency: "NGN"
  }
];
```

The amount is in minor units: `500_000` kobo is ₦5,000 at scale two. If no
amount is supplied, the current Bachs fixture default is `5_000_000`; set it
explicitly when your application order is ₦5,000.

The CLI executes selected tests sequentially by default. Concurrency belongs to
the scenario itself and is preserved inside that run. Use the exact name:

```bash
npx bachsproof test --name "concurrent duplicates stay idempotent"
```

Use a fresh reference for each test when using manual references. Automatic
preparation is safer for a complete suite because it creates fresh records for
the selected scenarios.
