## `createPayment(context)`

```ts
type PaymentReferenceCreator = (context: {
  scenario: ScenarioName;
  amountMinor: number;
  currency: string;
  paymentIndex: number;
  paymentCount: number;
}) => string | Promise<string>;
```

The callback is implemented by your application test code. It must create an
isolated payment, order, invoice, or deposit and return the fresh non-empty
reference that your webhook handler understands.

| Property | Type | Purpose |
| --- | --- | --- |
| `scenario` | `ScenarioName` | Identifies the scenario being run. |
| `amountMinor` | `number` | Expected integer amount in minor units. |
| `currency` | `string` | Three-letter currency code used by the test event. |
| `paymentIndex` | `number` | Zero-based position within this scenario. |
| `paymentCount` | `number` | Total references BachsProof needs for this scenario. |

`paymentIndex` and `paymentCount` matter most for
`concurrent-unique-payments`, where the callback runs once for each distinct
payment. Every call must return a different fresh reference. BachsProof also
rejects a reference reused by another selected test.

`amountMinor` is not a major-unit decimal. For a two-decimal currency such as
NGN, `500_000` means ₦5,000. Do not convert it through a floating-point major
unit before saving it.

## `verify(reference, context?)`

```ts
type FinancialVerifier = (
  reference: string,
  context?: FinancialVerificationContext
) => FinancialVerificationInput | Promise<FinancialVerificationInput>;
```

The callback must read committed state from the same isolated database or test
service that handled the webhook. It must not copy expected values from
`context`, an HTTP response, a cached balance, or an event body.

### Return contract

| Property | Type | Required? | Purpose |
| --- | --- | --- | --- |
| `reference` | `string` | Yes | Must equal the requested reference. |
| `creditCount` | `number` | Yes | Number of committed credit records for the reference. |
| `creditedAmountMinor` | `number` | Yes | Integer sum of committed credit amounts in minor units. |
| `currency` | `string` | Yes | Three-letter currency of the observed records. |
| `status` | `string` | No | Application status included in reports. |
| `pending` | `boolean` | No | `true` while asynchronous work can still change the state. |
| `ledgerEntries` | `LedgerEntry[]` | No | Optional committed entries used as report evidence. |

The smallest valid response is:

```js
export async function verify(reference) {
  return {
    reference,
    creditCount: 0,
    creditedAmountMinor: 0,
    currency: "NGN"
  };
}
```

That response is a contract example, not a real financial check. A real
callback must query the application store.

### `ledgerEntries` schema

```ts
type LedgerEntry = {
  id: string;
  type: string;
  amountMinor: number;
  currency?: string;
};
```

Every supplied entry requires `id`, `type`, and a non-negative integer
`amountMinor`. `currency`, when supplied, must be a three-letter string. The
array is optional, but its entries are not partially optional. For example, an
entry with `id` and `amountMinor` but no `type` fails runtime validation at
`ledgerEntries[0].type`.

### Complete database-backed response

```js
function toSafeMinorUnits(value) {
  const number = typeof value === "bigint" ? Number(value) : Number(value);
  if (!Number.isSafeInteger(number)) {
    throw new Error("Financial amount exceeds JavaScript safe integer range");
  }
  return number;
}

export async function verify(reference, context) {
  const payment = await prisma.payment.findUnique({ where: { reference } });
  const credits = await prisma.walletCredit.findMany({ where: { reference } });
  const unfinishedWorkerStates = new Set([
    "QUEUED", "WAITING", "PROCESSING", "RETRY_SCHEDULED", "RETRYING"
  ]);

  return {
    reference,
    creditCount: credits.length,
    creditedAmountMinor: credits.reduce(
      (total, credit) => total + toSafeMinorUnits(credit.amountMinor),
      0
    ),
    currency: payment?.currency ?? "NGN",
    status: payment?.status ?? "NOT_FOUND",
    pending: !payment || unfinishedWorkerStates.has(payment.workerStatus),
    ledgerEntries: credits.map((credit) => ({
      id: String(credit.id),
      type: String(credit.type),
      amountMinor: toSafeMinorUnits(credit.amountMinor),
      currency: credit.currency
    }))
  };
}
```

The `prisma`, `payment`, and `walletCredit` names are application schema names.
Adapt them for wallets, orders, invoices, or double-entry ledger tables. A
PostgreSQL `BIGINT` becomes JavaScript `bigint` in Prisma; convert it only after
checking the safe integer range.

### Pending and bounded observation

`pending: true` means the callback found work that can still change financial
state, such as a queued or retrying worker. A payment row whose business status
is `PENDING` does not by itself prove that webhook processing is still underway;
read the worker state your application actually uses. BachsProof polls until
`completionDeadlineMs`, and it observes an ineligible no-credit result for the
bounded `negativeObservationWindowMs`. Neither deadline is a guarantee that a
future job cannot write a credit.

The `context` argument separates expected and observed information:

- `context.expected` and `context.expectedOutcome` describe what the scenario
  should produce;
- `context.events`, `eventIdentifiers`, and `deliveries` describe what was sent;
- the object returned by `verify` describes what the application committed;
- the core compares the two and evaluates the financial invariants.

Return actual records even when the result is surprising. That is how a
duplicate, missing, wrong-currency, or wrong-amount credit becomes a useful
failure instead of being hidden by the verifier.
