## Configuration-based API

Import these public functions from `@bachsproof/cli`:

```ts
import { loadConfig, runConfig, summarizeRuns } from "@bachsproof/cli";
```

| Export | Signature | Purpose |
| --- | --- | --- |
| `loadConfig` | `loadConfig(configPath?)` | Loads and validates the existing `.mjs`, `.js`, `.cjs`, or TypeScript config. |
| `runConfig` | `runConfig(config, { testName? })` | Runs one exact named test or the complete configured suite. |
| `summarizeRuns` | `summarizeRuns(results)` | Produces pass/fail, verification, violation, and duration totals. |

`loadConfig()` resolves the path from the current working directory. The loaded
config includes its `createPayment`, `verify`, polling, and CLI-level Bachs
signing settings. The returned run objects have `{ name, result }`.

```ts
const config = await loadConfig("bachsproof.config.mjs");
const runs = await runConfig(config, { testName: "sequential duplicate webhook" });
const summary = summarizeRuns(runs);

for (const { name, result } of runs) {
  console.log(name, result.passed);
  console.log(result.report.expected, result.report.observed);
  console.log(result.report.verification?.violations ?? []);
  console.log(result.report.errors);
}

process.exitCode = summary.failed === 0 ? 0 : 1;
```

Omit `testName` to run every configured test. See the
[programmatic walkthrough](/advanced/programmatic-api) for a complete script.

## Direct Core API

```ts
import { BachsProof, writeReport } from "@bachsproof/core";
import { bachsAdapter, signBachsWebhook } from "@bachsproof/bachs";

const baseProvider = bachsAdapter({ mode: "mock" });
const secret = process.env.BACHS_WEBHOOK_SECRET;
if (!secret) throw new Error("BACHS_WEBHOOK_SECRET is required");
const provider = {
  ...baseProvider,
  headersForBody(event, body) {
    return {
      ...(baseProvider.headers?.(event) ?? {}),
      ...signBachsWebhook(body, secret)
    };
  }
};

const runner = new BachsProof({
  provider,
  target: { baseUrl: "http://127.0.0.1:3000", webhookPath: "/webhooks/bachs" },
  createPayment: ({ amountMinor, currency }) =>
    applicationTestApi.createPayment({ amountMinor, currency }).then((payment) => payment.reference),
  verify: (reference, context) => applicationTestApi.verify(reference, context),
  financialVerification: {
    completionDeadlineMs: 10_000,
    pollIntervalMs: 25,
    negativeObservationWindowMs: 250
  }
});

const result = await runner.run({
  scenario: "sequential-duplicate-webhook",
  amountMinor: 500_000,
  currency: "NGN"
});

if (!result.passed) await writeReport(result.report, "artifacts/bachsproof.json");
```

The Core API does not read CLI config and does not automatically add webhook
signatures. Wrap the provider as shown when the target validates Bachs
signatures. `headersForBody` must sign the body it receives so tampered-payload
and invalid-signature scenarios retain their intended behavior.

## Core exports

| Export | Purpose |
| --- | --- |
| `BachsProof` | High-level runner with preparation, delivery, verification, and reports. |
| `preparePaymentReferences` | Resolve missing references with `createPayment`. |
| `RaceController` | Optional local checkpoint barrier. |
| `verifyPaymentState` | Evaluate the five financial invariants. |
| `verifyWithCallback` | Validate and poll a verifier. |
| `writeReport` | Write a JSON report and create its parent directory. |
| `redactSecrets` | Remove common secret formats from diagnostic strings. |

The optional `@bachsproof/sdk` is application-side checkpoint instrumentation;
it is not required by either programmatic approach.
