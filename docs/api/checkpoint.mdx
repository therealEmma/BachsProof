---
title: "Checkpoint API"
description: "Reference for the optional checkpoint runner and SDK surfaces."
---

Core runner configuration:

```ts
checkpoint?: {
  name: string;
  timeoutMs?: number;
}
```

SDK exports:

| Function | Purpose |
| --- | --- |
| `configureCheckpoint` | Set process-wide context or explicitly allow request headers |
| `disableCheckpoints` | Remove process-wide state and header activation |
| `isCheckpointEnabled` | Check whether a barrier context is active |
| `runWithCheckpointContext` | Run code under a supplied request context |
| `checkpoint` | Announce arrival at a named barrier and wait for release |
| `checkpointMiddleware` | Attach request context when both opt-in switches are enabled |
| `getCheckpointContext` | Read the current context |

Checkpoint calls are no-ops when disabled. Enabled request contexts contain
`controllerUrl`, `sessionId`, `participantId`, `token`, and an optional timeout.
The controller authenticates the token and participant before it can affect a
barrier. This is optional test instrumentation, not a production lock or
authorization mechanism.
