---
title: "Report structure"
description: "Reference for BachsProofReport, deliveries, verification, and replay metadata."
---

Important fields on `BachsProofReport`:

| Field | Meaning |
| --- | --- |
| `reportVersion` | Current report shape, `"1.1"` |
| `scenario` | Scenario that ran |
| `provider`, `mode` | Adapter identity, such as `Bachs` and `mock` |
| `paymentReference` | Primary reference |
| `event`, `expected` | Primary structured event and expected state |
| `observed` | First observed financial state |
| `payments` | Per-reference observations for unique payments |
| `verificationMode` | `callback` or `none` |
| `financiallyVerified` | Whether committed state was inspected; it can be true even when rules failed |
| `verification` | Overall pass plus all `InvariantViolation` objects |
| `deliveries` | HTTP attempts, statuses, response bodies, and errors |
| `checkpoints` | `arrival`, `release`, or `abort` trace events |
| `errors` | Preparation, delivery, configuration, and invariant messages |
| `replay` | Seed, concurrency, checkpoint, controlled flag, and limitation note |
| `startedAt`, `completedAt` | ISO timestamps |

`BachsProofResult.passed` is false when errors exist or a financial verification
result contains violations. Without a verifier, delivery success can return
`passed: true` while `financiallyVerified` remains false. The report stores a
structured event object, not the exact raw serialized body or all request
headers; replay therefore does not claim byte-for-byte reproduction.

The CLI explains the existing fields using five display states:

| CLI wording | Report evidence |
| --- | --- |
| Financial verification not configured | `verificationMode: "none"` |
| Financial verification configured; did not run | Callback mode, but preparation or run setup stopped before an observation. |
| Financial verification attempted; could not complete | Callback mode with a verifier error, timeout, or invalid callback response. |
| Financial verification completed | `financiallyVerified: true` and no violations. |
| Financial verification completed; financial violations detected | `financiallyVerified: true` and one or more `verification.violations`. |

These are CLI labels, not new report fields, so the v1.1 report schema remains
compatible.
