---
title: "Concurrent duplicate credit"
description: "Check duplicate-credit handling with ordinary concurrent requests."
---

BachsProof creates one payment and sends overlapping successful webhooks for
the same reference. The application should commit one credit. Two credits fail
`INV-001` and show the actual duplicate amount in the report.

This is ordinary concurrency. It can expose a race, but it cannot guarantee
that every operating-system and database interleaving is reproduced.
