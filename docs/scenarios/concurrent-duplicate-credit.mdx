---
title: "Concurrent duplicate credit"
description: "Exercise a duplicate-credit race with concurrent webhook deliveries."
---

## What problem does it test?

Two requests try to credit the same ₦5,000 payment at the same time. A handler
that reads “not completed” and writes later can let both requests add
`500_000` kobo.

## What BachsProof sends

It creates one eligible `collection.succeeded` event and sends the same body to
the configured webhook in a concurrent wave:

```js
{
  name: "concurrent duplicate ₦5,000 credit",
  scenario: "concurrent-duplicate-credit",
  concurrency: 2,
  amountMinor: 500_000,
  currency: "NGN",
  reference: "prepared-payment"
}
```

The runner uses `Promise.allSettled` so every delivery response and error stays
in the report. `reference` must identify an isolated application payment unless
`syntheticReferences: true` is explicitly selected.

## What the application should do

Authenticate both deliveries, match the reference to the stored order, and
make the credit operation idempotent. One request may win; the other should be
recognized as a duplicate without adding money. Both may return 2xx, but the
committed state must contain one credit.

## Expected outcome and failure

One `500_000`-kobo credit is expected. Two credits fail `INV-001` and, because
the aggregate is now `1_000_000`, also fail `INV-002`. A missing credit fails
`INV-003`. `INV-005` applies when the expected count is present but the total is
wrong, so it is not the duplicate-count rule. A delivery error or unexpected
HTTP status fails the delivery layer before financial evaluation.

Ordinary concurrency is not deterministic: the OS may let one request finish
before the other reads. Add [controlled concurrency](/advanced/controlled-concurrency)
to coordinate a named after-read point. The application still needs an atomic
database design.

## Internal implementation

`BachsProof.run` in `packages/core/src/orchestrator.ts` creates one provider
event and calls `deliver` once per participant. Without a checkpoint it settles
the promises with `settleConcurrentDeliveries`. With a checkpoint it creates a
`RaceController`, waits for all arrivals, releases the barrier, and records the
trace. `createBachsMockFixture` in `packages/bachs/src/fixtures.ts` creates the
event.
