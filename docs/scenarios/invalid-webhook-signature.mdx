---
title: "Invalid webhook signature"
description: "Check that an event with invalid authentication is rejected."
---

## What is being tested?

This test sends a valid-looking payment event with a deliberately invalid
`X-Bachs-Signature-V2` header.

## Why does it matter?

The signature lets your application check that the event came from a trusted
sender and was not changed. Processing an unauthenticated event can create
money from an attacker-controlled request.

## What BachsProof does

BachsProof sends a valid-shaped `collection.succeeded` body with an invalid
signature and normally expects a 4xx response.

Run it with:

```bash
pnpm exec bachsproof test --name "invalid webhook signature"
```

## What the application should do

Verify the signature before business processing. Reject the request, leave the
financial store unchanged, and record a security signal if your application
needs one.

## Pass and failure

A pass rejects the event and commits zero credits. With `verify()`, `INV-004`
checks the financial result. A 4xx alone is only an HTTP result; it does not
prove that no credit was saved. This test does not cover secret rotation or a
real Bachs delivery.
