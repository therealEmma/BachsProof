---
title: "Invalid webhook signature"
description: "Check that an event with an invalid signature is rejected."
---

## What problem does it test?

The event looks valid, but its authentication proof is wrong. The handler must
not process it as a payment or add a ₦5,000 credit.

## What BachsProof sends

It sends a valid-shaped `collection.succeeded` body with a deliberately invalid
`X-Bachs-Signature-V2` header and expects `4xx`:

```js
{
  name: "invalid signature is rejected",
  scenario: "invalid-webhook-signature",
  expectedStatus: "4xx",
  amountMinor: 500_000,
  currency: "NGN"
}
```

The valid event shape isolates signature authentication from JSON parsing and
business validation.

## What the application should do

Reject before business processing, record an appropriate security signal if
desired, and leave the financial store unchanged. Do not use an invalid event
as a reason to alter a payment.

## Expected outcome and failure

Zero credits are expected; with `verify`, `INV-004` checks the financial result.
A 4xx alone is only an HTTP observation. This does not test secret rotation or
a live Bachs delivery.

## Internal implementation

`createBachsScenario` in `packages/bachs/src/fixtures.ts` supplies a
`t=0,v1=` header containing zeroed digest bytes and marks the delivery's
expected status as `4xx`.
