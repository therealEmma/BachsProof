---
title: "Invalid webhook signature"
description: "Check that an event with an invalid signature is rejected."
---

## What problem does it test?

The event looks valid, but its authentication proof is wrong. The handler must
not process it as a payment or add a ₦5,000 credit.

## What BachsProof sends

It sends a valid-shaped `collection.succeeded` body with a deliberately invalid
`X-Bachs-Signature-V2` header. The generated test expects a `4xx` response.

```js
{
  name: "invalid signature is rejected",
  scenario: "invalid-webhook-signature",
  expectedStatus: "4xx",
  amountMinor: 500_000,
  currency: "NGN"
}
```

## Expected result and failure

The request should be rejected and zero credits should be committed. A 4xx
alone is only an HTTP observation; configure `verify` so `INV-004` checks the
financial result. The scenario does not test secret rotation or a live Bachs
delivery. The invalid header is created in `packages/bachs/src/fixtures.ts`.
