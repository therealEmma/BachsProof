---
title: "Malformed webhook"
description: "Check that invalid JSON is rejected safely."
---

## What problem does it test?

Your endpoint should not crash or create a financial effect when the request
body is not valid JSON. A parser failure must not become a ₦5,000 credit.

## What BachsProof sends

It sends the body `{"invalid":` and expects a `4xx` response:

```js
{
  name: "malformed JSON is rejected",
  scenario: "malformed-webhook",
  expectedStatus: "4xx",
  amountMinor: 500_000,
  currency: "NGN"
}
```

This is not a Bachs event; it exercises the parser/error boundary.

## What the application should do

Return a controlled client error, leave the financial store unchanged, and
avoid accepting a partially parsed body. It should not expose secrets in the
error response.

## Expected outcome and failure

The application should safely reject the body and commit zero credits. With a
verifier, `INV-004` checks that no ineligible financial effect appeared. This
does not prove that every malformed content type or oversized body is handled.

## Internal implementation

The body override and expected status are created by `createBachsScenario` in
`packages/bachs/src/fixtures.ts`; core records the response in `deliver`.
