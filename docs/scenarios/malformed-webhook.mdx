title: "Malformed webhook"
description: "Check that invalid JSON is rejected safely."
---

## What is being tested?

This test sends a request body that is not valid JSON.

## Why does it matter?

Parser errors are normal input failures. They must not crash the route, expose
secrets, or accidentally create a financial record from a partially read body.

## What BachsProof does

BachsProof sends the body `{"invalid":` and normally expects a 4xx response. It
does not pretend that this body is a Bachs event.

Run it with:

```bash
pnpm exec bachsproof test --name "malformed webhook"
```

## What the application should do

Return a controlled client error, leave the financial store unchanged, and
avoid parsing or processing incomplete data. Do not include secrets in the
error response.

## Pass and failure

A pass rejects the body with the configured 4xx status and commits zero credits.
With `verify()`, `INV-004` confirms that no financial effect was saved. A 4xx
alone checks only the HTTP boundary.
