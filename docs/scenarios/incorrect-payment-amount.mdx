---
title: "Incorrect payment amount"
description: "Prevent fulfilment when the event amount does not match the order."
---

## What problem does it test?

Your order expects ₦5,000 (`500_000` kobo), but a successful-looking event
reports one minor unit more. The application must not credit the order until
the event amount matches the stored amount.

## What BachsProof sends

It creates a valid-shaped `collection.succeeded` event with the same reference
and currency but `amountMinor + 1`:

```js
{
  name: "wrong amount is not fulfilled",
  scenario: "incorrect-payment-amount",
  amountMinor: 500_000,
  currency: "NGN"
}
```

The application may return 2xx while deciding not to fulfil a valid-shaped but
business-invalid event.

## What the application should do

Compare integer amount and scale with the amount stored for the reference. Do
not trust the event's amount as the order price and do not create a credit for
`500_001` minor units when the order expects `500_000`.

## Expected outcome and failure

Zero credits are expected; a credit fails `INV-004`. BachsProof does not know
your order table and cannot decide whether the mismatch is correct without your
application's verification callback.

## Internal implementation

`createBachsScenario` calls `createBachsMockFixture` with `amountMinor + 1` and
uses `expectedNoCredit` for the reference. The mutation is in
`packages/bachs/src/fixtures.ts`.
