---
title: "Concurrent unique payments"
description: "Check that independent payments remain independent under load."
---

## What problem does it test?

Two different customers pay at the same time. Processing one payment must not
credit the other customer or make either payment disappear. For example, two
customers can each deposit ₦5,000 and should receive one credit each.

## What BachsProof sends

It creates one eligible `collection.succeeded` event for every distinct
reference and delivers them concurrently:

```js
{
  name: "two unique ₦5,000 payments",
  scenario: "concurrent-unique-payments",
  references: ["payment-a", "payment-b"],
  concurrency: 2,
  amountMinor: 500_000,
  currency: "NGN"
}
```

The references must be non-empty, distinct, and match `concurrency`. Automatic
preparation calls `createPayment` once per payment.

## What the application should do

Use each event's own reference and customer/order association. A credit for
`payment-a` must not be linked to `payment-b`, even though both requests arrive
in one delivery wave. Each transaction should protect only its own payment.

## Expected outcome and failure

Each reference should have exactly one `500_000`-kobo NGN credit. BachsProof
verifies each reference independently, so an over-credit on one cannot be hidden
by an under-credit on another. Missing credits fail `INV-003`; duplicates fail
`INV-001`; wrong totals or currencies fail `INV-002` and possibly `INV-005`.

## Internal implementation

`BachsProof.run` creates one event per reference, delivers them with
`settleConcurrentDeliveries`, then creates one verification case per event and
stores them in `report.payments`. `preparePaymentReferences` in
`packages/core/src/preparation.ts` handles one callback call per payment when
references are not supplied.
