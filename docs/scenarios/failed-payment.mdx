---
title: "Failed payment"
description: "Prevent fulfilment when a collection attempt failed."
---

## What problem does it test?

The collection attempt failed. A failed attempt must not be treated as a paid
order or wallet deposit. The customer must not receive a ₦5,000 credit merely
because a checkout or charge reference exists.

## What BachsProof sends

It creates a documented-shaped `collection.failed` event with `status:
"FAILED"` and the configured amount and currency. Delivery is sequential and
normally accepted by a handler that records the event without crediting:

```js
{
  name: "failed collection is not fulfilled",
  scenario: "failed-payment",
  amountMinor: 500_000,
  currency: "NGN"
}
```

## What the application should do

Preserve the failed state and avoid fulfilment. A later successful attempt must
have its own valid event and be matched to the correct stored order. The
existence of a failed event is not a reason to credit the configured amount.

## Expected outcome and failure

Zero credits are expected; a credit fails `INV-004`. A failed collection can
leave a checkout open for another attempt; this fixture does not model that
retry.

## Internal implementation

`createBachsScenario` constructs a `collection.failed` envelope with settlement
and fee fields set to `null`, `eligible: false`, and `expectedNoCredit`. The
synthetic event is constructed in `packages/bachs/src/fixtures.ts`, not
received from a live provider.
