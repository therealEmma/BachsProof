---
title: "Incomplete checkout"
description: "Prevent fulfilment when checkout completed without a collected payment."
---

## What problem does it test?

Finishing a checkout screen does not always mean money was collected. A
`checkout.completed` event with `payment_status: "no_payment_required"` and no
charge must not credit a wallet. For ₦5,000, the correct credit count is zero.

## What BachsProof sends

The plan sends one completed, payment-mode checkout with a non-paying status and
`charge: null`. It normally expects 2xx because the application may safely
record or acknowledge an unfulfillable event.

```js
{
  name: "checkout without collection is not a deposit",
  scenario: "incomplete-checkout",
  amountMinor: 500_000,
  currency: "NGN"
}
```

## What the application should do

Require a paid status and an actual charge before crediting. A checkout screen
completing is a user-interface state, not proof that Bachs collected ₦5,000.

## Expected outcome and failure

The verifier should observe zero credits. A credit violates `INV-004`. For an
asynchronous application, return `pending: true` while unfinished work remains
and allow the negative observation window to elapse.

## Internal implementation

`checkoutFixture` in `packages/bachs/src/fixtures.ts` sets
`payment_status: "no_payment_required"`, `charge: null`, and `eligible: false`.
`expectedNoCredit` sets `expectedCreditCount` to zero.
