---
title: "Incomplete checkout"
description: "Prevent fulfilment when checkout completed without a collected payment."
---

## What problem does it test?

Finishing a checkout screen does not always mean money was collected. A
`checkout.completed` event with `payment_status: "no_payment_required"` and no
charge must not credit a wallet. For the ₦5,000 example, the correct credit
count is zero, not one `500_000`-kobo entry.

## What BachsProof sends

The Bachs plan sends one `checkout.completed` envelope with a completed checkout,
payment mode, a non-paying status, and `charge: null`. The normal HTTP
expectation is 2xx because the application can safely record or acknowledge an
unfulfillable event.

```js
{
  name: "checkout without collection is not a deposit",
  scenario: "incomplete-checkout",
  amountMinor: 500_000,
  currency: "NGN"
}
```

## Expected result and failure

The verifier should observe zero credits. A credit violates `INV-004`. An
immediate zero is not enough for an asynchronous application; allow the
negative observation window and return `pending: true` while unfinished work is
still possible. The fixture plan is in `packages/bachs/src/fixtures.ts`.
