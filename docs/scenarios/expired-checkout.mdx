---
title: "Expired checkout"
description: "Prevent fulfilment when a checkout expires without collection."
---

## What problem does it test?

An open checkout can expire. Expiry is not payment success, so an expired
checkout must not add a ₦5,000 wallet credit.

## What BachsProof sends

It sends one `checkout.expired` envelope without a charge and marks it
ineligible. The normal HTTP expectation is 2xx. This fixture is an event
handling test, not a live provider expiry.

```js
{
  name: "expired checkout does not credit",
  scenario: "expired-checkout",
  amountMinor: 500_000,
  currency: "NGN"
}
```

## What the application should do

Record the expiry if useful, but do not fulfil the order or credit the wallet. A
later successful collection is a separate event and must be matched to the
correct stored payment.

## Expected outcome and failure

The verifier should observe zero credits; any credit fails `INV-004`. A later
valid success may still arrive in a real lifecycle, which is why
[delayed payment confirmation](/scenarios/delayed-payment-confirmation) is a
separate scenario.

## Internal implementation

`checkoutFixture` in `packages/bachs/src/fixtures.ts` sets the checkout as
expired, with no payment status and no charge. The scenario's expected state is
created by `expectedNoCredit`.
