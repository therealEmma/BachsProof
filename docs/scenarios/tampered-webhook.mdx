---
title: "Tampered webhook"
description: "Check that changing a signed body is rejected."
---

## What is being tested?

This test changes a signed request after the signature was created. The changed
request looks like a successful payment but no longer matches the signature.

## Why does it matter?

An attacker or broken proxy could change an amount or reference. If the handler
verifies one body but parses another, it may credit the wrong payment.

## What BachsProof does

BachsProof signs the original event, changes the amount by one minor unit, and
sends the changed body with the original signature. The generated test normally
expects a 4xx response.

Run it with:

```bash
pnpm exec bachsproof test --name "tampered webhook"
```

## What the application should do

Capture the original raw request bytes, verify the signature over those exact
bytes, and parse the JSON only after verification. Reject the changed body and
create no credit.

## Pass and failure

A pass rejects the request and the verifier observes zero credits. The 4xx
checks transport behavior; `INV-004` checks the saved financial state. If the
target does not verify signatures, this scenario cannot test that security
boundary.
