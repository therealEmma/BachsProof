---
title: "Webhook authentication and signing"
description: "Verify Bachs test webhooks using the original raw body."
---

Enable the CLI's Bachs test signing with:

```js
signing: {
  type: "bachs",
  secret: process.env.BACHS_WEBHOOK_SECRET
}
```

BachsProof signs the exact body it sends. The helper returns
`X-Bachs-Signature-V2` in the form:

```text
t=<unix timestamp>,v1=<hex HMAC-SHA256 digest>
```

The signed message is the timestamp, a period, and the original UTF-8 body.
For tampered-body tests, BachsProof signs one body and deliberately sends
another, so a correct verifier must reject it.

## HMAC is authentication, not encryption

HMAC is a shared-secret checksum. BachsProof and your webhook handler both know
the secret, so the handler can calculate the checksum again and compare it with
the header. If the body changed, the checksum changes. If the sender does not
know the secret, it cannot create the right checksum.

HMAC does **not** hide the JSON body. It is not encryption. Use HTTPS to protect
the request while it travels over the network, and keep the signing secret out
of source control and production logs.

## Verify before parsing

In a Node/TypeScript application, use the official SDK on raw bytes or the raw
text supplied by your framework:

```ts
const rawBody = req.body; // Buffer captured by route-local raw middleware
const event = webhooks.constructEvent(
  rawBody,
  req.headers,
  process.env.BACHS_WEBHOOK_SECRET!
);
```

The reference wallet uses `express.raw` on the webhook route and then calls
`webhooks.constructEvent` before `JSON.parse`/Zod normalization. The SDK checks
signature validity and timestamp tolerance. It does not store processed event
IDs or run your business handler; your application owns those steps.

Never reuse a production secret in local or CI tests. Synthetic signing proves
that your raw-body verification path works; it does not prove that Bachs sent
or settled a live payment. The [official Bachs webhook guide](https://docs.bachs.io/guides/webhooks/overview)
describes the live headers and secret-management rules.
