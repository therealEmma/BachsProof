---
title: "Supported payment events"
description: "The Bachs event types represented by the current adapter."
---

The current adapter validates and generates five one-time payment lifecycle
event types:

| Event | Meaning used by BachsProof | Fulfilment eligibility in the adapter |
| --- | --- | --- |
| `checkout.completed` | Checkout finished; it may have no collected charge | Only when it is payment mode, completed, paid, has a charge, and has currency |
| `checkout.expired` | An open checkout expired | Never |
| `collection.succeeded` | A collection succeeded | When `data.status` is `SUCCEEDED` |
| `collection.underpaid` | Only part of the expected amount arrived | Never |
| `collection.failed` | A collection attempt failed | Never |

`checkout.completed` and `collection.succeeded` can describe the same underlying
payment. BachsProof deliberately sends that pair in the cross-event duplicate
scenario. Event IDs identify deliveries; a local reference and provider
payment/checkout IDs help the application identify the business payment.

These are the only event families implemented by `packages/bachs/src/fixtures.ts`.
The current adapter does not claim support for subscriptions, payouts, refunds,
disputes, or Connect events. Check the [official Bachs webhook index](https://docs.bachs.io/llms.txt#webhooks)
for the provider's current contract before extending the adapter.
