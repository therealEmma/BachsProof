---
title: "Testing a Bachs integration"
description: "Combine official Bachs provider testing with application-side financial verification."
---

Use the official Bachs sandbox and webhook tools to exercise provider-side
behaviour. Use BachsProof to test the financial result produced by your own
application after an event reaches its webhook handler.

## Provider-side testing

The official Bachs workflow covers creating a checkout, receiving provider
events, verifying real signatures, forwarding sandbox events locally, and
replaying provider events. Follow the [Bachs webhook guide](https://docs.bachs.io/guides/webhooks/overview)
and [local testing guide](https://docs.bachs.io/developer-portal/local-testing) for
that work.

## Application-side correctness testing

BachsProof uses a local mock adapter and an application-specific callback:

```js
import { bachsAdapter } from "@bachsproof/cli";

export default {
  provider: bachsAdapter({ mode: "mock" }),
  target: {
    baseUrl: "http://127.0.0.1:3000",
    webhookPath: "/webhooks/bachs"
  },
  signing: { type: "bachs", secret: process.env.BACHS_WEBHOOK_SECRET },
  requireFinancialVerification: true,
  tests
};
```

The local flow is:

1. create or prepare an isolated application payment reference;
2. let the adapter build a Bachs-shaped event;
3. sign the raw body if your route verifies signatures;
4. deliver it to the existing test webhook;
5. have `verify` read the committed payment and ledger state; and
6. compare that state with the scenario's expected outcome.

The callback is where application-specific knowledge belongs. It may read a
wallet table, ledger, payment record, or service-owned projection. BachsProof
does not infer that schema and does not treat a successful HTTP response as
financial proof.

Use the Bachs sandbox separately when you need to validate checkout creation,
provider event delivery, or a genuine provider-side payment flow. Use BachsProof
when you need to verify the consequences of those payment states inside your
application.

<Warning>
Synthetic webhook success is not proof of a completed checkout, collection, or
settlement. It tests your application boundary and, with `verify`, the state your
application commits in response.
</Warning>
