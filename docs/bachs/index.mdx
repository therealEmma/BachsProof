title: "Bachs integration"
description: "Use BachsProof alongside official Bachs integration and webhook tools."
---

BachsProof is an independent, unofficial application-side testing framework for
Bachs integrations. Its Bachs adapter creates deterministic synthetic events
shaped like the documented Bachs webhook envelopes. It does not call Bachs,
create a checkout, or verify provider settlement.

## Keep the responsibilities separate

| Concern | Official Bachs tools | BachsProof |
| --- | --- | --- |
| Checkout creation and provider payment flow | Use the Bachs SDK, sandbox, and checkout documentation | Not performed |
| Real signed provider webhooks and provider delivery records | Use Bachs webhooks, Developer Portal, CLI forwarding, and replay tools | Not represented as live provider evidence |
| Application webhook validation and event handling | Your application receives and processes the event | Sends controlled synthetic requests to the same test endpoint |
| Payment matching, idempotency, ledger writes, and wallet crediting | Implemented by your application | Observed through your `verify` callback |
| Financial outcome checks | Application-specific assertions remain your responsibility | Applies five reusable financial invariants to observed state |

This is a complementary workflow. First use the official Bachs resources to
build and inspect the provider integration. Then use BachsProof against an
isolated application process and test database to verify what that application
does with payment events.

Useful official references include the [webhook setup guide](https://docs.bachs.io/guides/webhooks/overview),
[local webhook testing guide](https://docs.bachs.io/developer-portal/local-testing),
[checkout guide](https://docs.bachs.io/guides/checkout/checkout-sessions), and
[idempotency guide](https://docs.bachs.io/guides/idempotency).

## What the adapter does

- Creates provider-shaped checkout and collection events.
- Builds the 15 scenario plans used by the CLI.
- Serializes only the provider envelope sent over HTTP.
- Signs a raw test body with `signBachsWebhook` when requested.
- Parses decimal-string amounts exactly with `bigint` before converting to
  provider-neutral integer minor units.
- Normalizes eligibility for the core's expected-state comparison.

## What it does not do

- It does not create a Bachs checkout or call a Bachs API.
- It does not retrieve a live payment or prove settlement.
- It does not emulate provider retry timing, a real customer, or every Bachs
  event family.
- It does not replace your application's order matching, durable deduplication,
  or ledger transaction.

The reference wallet uses the official `@bachs/sdk` server-side webhook helper
when a secret is configured. That application boundary is separate from
BachsProof's local mock adapter. Use the Bachs sandbox separately for provider-
side evidence.
