---
title: "Payment eligibility"
description: "Understand when the adapter considers an event fulfilment-eligible."
---

Eligibility answers a narrow question: should this synthetic event represent a
payment that is allowed to create the expected financial effect? It is not a
database lookup and it is not a guarantee that your application's order is
eligible.

The current adapter decides:

- `collection.succeeded` is eligible when its status is `SUCCEEDED`;
- `checkout.completed` is eligible only when it is a payment-mode checkout,
  status is `completed`, payment status is `paid`, a charge exists, and a
  currency exists;
- `checkout.expired`, `collection.underpaid`, and `collection.failed` are
  ineligible.

For a ₦5,000 wallet deposit, the adapter's expected eligible state is one credit
of `500_000` NGN minor units. An ineligible fixture's expected credit count is
zero. The application's handler must still match the event to its own order,
amount, currency, customer, and provider transaction before fulfilment.

The rules are implemented by `normalizeBachsWebhookEvent` and
`expectedBachsState` in `packages/bachs/src/fixtures.ts`. The application should
not treat this test-adapter decision as a replacement for retrieving and
matching complete provider state in a live integration.
