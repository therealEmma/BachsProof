---
title: "Test execution lifecycle"
description: "Follow one PayProof run from selection to report."
---

Every run follows the same broad path:

<Steps>
  <Step title="Select a scenario">
    The CLI selects every configured test, or one test when `--name` is used.
    Programmatic callers pass a `RunOptions` object to `payproof.run()`.
  </Step>
  <Step title="Prepare references">
    Manual references take precedence. Synthetic references are allowed only
    when explicitly enabled. Otherwise `createPayment` is called for each
    required payment and every returned reference is validated for emptiness and
    reuse.
  </Step>
  <Step title="Create the provider plan">
    The adapter builds one event or a provider-defined lifecycle plan. The
    plan describes event bodies, order, concurrency, expected HTTP status, and
    expected financial state.
  </Step>
  <Step title="Deliver the raw bodies">
    PayProof serializes the event, signs the exact body when configured, and
    sends it to `baseUrl + webhookPath`. Concurrent deliveries are settled with
    `Promise.allSettled`, so every delivery error remains visible.
  </Step>
  <Step title="Observe committed state">
    If `verify` is configured, PayProof calls it with each relevant reference and
    context. It polls within the configured bound when the callback returns
    `pending: true`.
  </Step>
  <Step title="Evaluate and report">
    The runner checks HTTP expectations, normalizes the callback result, applies
    the financial invariants, and records deliveries, errors, checkpoints, and
    timing in the report.
  </Step>
</Steps>

Expected state is diagnostic input to the comparison. It never replaces an
observation from the application.
