---
title: "Payment event generation"
description: "Understand what the provider adapter creates and what stays synthetic."
---

The Bachs adapter uses `mode: "mock"`. It generates local webhook envelopes
with documented event names and fields needed by the current scenarios. It does
not call a Bachs API, create a checkout, or settle money.

The serialized wire body contains only the provider envelope:

```json
{
  "id": "evt_example",
  "type": "collection.succeeded",
  "created_at": "2026-01-01T00:00:00.000Z",
  "organization_id": "acct_payproof_test",
  "data": {
    "charge_id": "ch_example",
    "checkout_id": "chk_example",
    "reference": "payment-123",
    "status": "SUCCEEDED",
    "amount": "5000.00",
    "currency": "NGN"
  }
}
```

The normalized fields used internally by the core are not added to the wire
body. This keeps the application test close to the provider envelope while
letting the provider-neutral runner compare references and amounts.

See [Bachs events](/bachs/events) for the exact fixture families and
limitations.
