---
title: "Webhook signing and delivery"
description: "Learn how PayProof signs raw test bodies and sends them to your route."
---

When `signing.type` is `"bachs"`, the CLI wraps the provider adapter and signs
the exact serialized body. The current helper creates the documented V2 header
from the timestamp and body using HMAC-SHA256.

```text
payload = timestamp + "." + raw_body
signature = HMAC-SHA256(secret, payload)
header = X-Bachs-Signature-V2: t=<timestamp>,v1=<signature>
```

The application must verify the original raw request body before JSON parsing.
The official Bachs Node SDK's `webhooks.constructEvent` helper performs the
provider verification and timestamp checks. See the [official SDK guide](https://docs.bachs.io/sdks/node#verify-webhooks).

PayProof sends:

- `content-type: application/json`;
- configured target headers;
- adapter signing/provider headers;
- optional checkpoint headers when controlled mode is enabled.

It records status, response body, event identifiers, participant identifiers,
timing, expected status, and delivery errors. It does not retry a failed HTTP
delivery on behalf of the scenario.

<Warning>
The test signing secret is not a Bachs API key. Keep it in the isolated test
environment and never use a production webhook secret in local examples.
</Warning>
