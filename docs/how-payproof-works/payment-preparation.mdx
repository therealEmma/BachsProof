---
title: "Payment preparation"
description: "Choose automatic, manual, or synthetic references without state contamination."
---

A webhook normally points to a payment or order that already exists in your
application. PayProof therefore needs a reference before it can test a real
application.

There are three modes:

| Mode | Use it when | Financial evidence |
| --- | --- | --- |
| Automatic `createPayment` | You want repeatable runs and fresh records | Can be real evidence when paired with `verify` |
| Manual `reference` / `references` | You already created isolated records | Can be real evidence when paired with `verify` |
| `syntheticReferences: true` | You are testing a fixture or adapter in isolation | Not evidence of application financial state |

Automatic preparation receives the scenario, amount in minor units, currency,
zero-based payment index, and payment count. It must return a non-empty fresh
reference. The CLI rejects references reused by another selected scenario.

The target application owns cleanup. PayProof never truncates your database or
calls a reset endpoint.
